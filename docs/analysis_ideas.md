# お題・分析アイデアの例

参加者が「何を作るか」を考えるときのヒントです。どのデータにも、実際の業務データで起きるような出来事（季節や天気の影響、トラブル、施策の効果）が含まれています。
審査基準の「Fabric の活用」「業務での再現性」「新規性」に沿って、使う Fabric の機能も添えています。

## データセットごとのアイデア

### 1. 小売・EC（01_retail_ec）

| アイデア | 使う Fabric の機能 | ヒント |
|---|---|---|
| 天気と売れ筋（アイス／ホット、来店客数、EC へのシフト）の分析 | ノートブック、Power BI | 店舗には最寄りの気象庁観測所を付けています。気象庁の過去データと結合してみてください |
| 価格改定の影響（数量・客単価・商品の乗り換え） | ウェアハウス（SQL）、Power BI | `product_price_history` で改定日がわかります |
| 新商品・季節限定商品の立ち上がりと定番化 | Power BI | 発売日・販売時期は `products` にあります |
| 会員の RFM 分析・ランク別の行動 | ノートブック | 店舗とオンラインの両方を使う会員もいます |
| 定期便の継続率・解約理由 | SQL、Power BI | `subscriptions` に開始日・解約日・理由があります |
| 配送遅延の要因分析（繁忙期・天候） | ノートブック | お届け予定日と実績、お届け先の都道府県があります |
| 店舗別・曜日別・時間帯別の需要予測 | ノートブック（Spark ML など） | 立地（オフィス街・観光地など）でパターンが違います |
| 家計調査と組み合わせたエリア分析 | Data Factory、Power BI | 総務省の家計調査（品目別支出）と都道府県・市で結合できます |

### 2. 製造・IoT（02_manufacturing_iot）

| アイデア | 使う Fabric の機能 | ヒント |
|---|---|---|
| センサー値の異常検知・故障の予兆検知 | Real-Time Intelligence（イベントハウス・KQL）、アクティベーター | 故障履歴（`failure_history`）を正解ラベルに使えます |
| ストリーミングでの監視ダッシュボード | イベントストリーム、リアルタイム ダッシュボード | `tools/replay_sensor_to_eventstream.py` で 1 分値を流せます |
| 稼働率・チョコ停（短時間停止）の分析（OEE） | KQL、Power BI | `status` 列で稼働・待機・停止がわかります |
| 外気温と設備負荷 | ノートブック | 工場は埼玉県熊谷市（気象庁「熊谷」） |
| 焙煎度・水分値の品質管理（規格外の検出） | SQL | `production_lots` に測定値と規格があります |

### 3. 営業・マーケティング（03_sales_marketing）

| アイデア | 使う Fabric の機能 | ヒント |
|---|---|---|
| チャネル別の CPA・商談化率・受注率・ROI | Power BI | 広告費 → リード → 商談 → 受注を ID でたどれます |
| 初回対応の速さと商談化率 | SQL | `leads.created_at` と `first_contact_at` |
| 商談ステージの滞留・パイプライン予測 | ノートブック | `opportunity_stage_history` |
| 会社名の名寄せ（表記ゆれ） | ノートブック、Dataflow Gen2 | 「（株）」「株式会社」、半角カナなどが混在しています |
| 媒体の計測値と CRM のずれの分析 | SQL | `platform_conversions` とリード数は一致しません |

### 4. 人事・勤怠（04_hr_attendance）

| アイデア | 使う Fabric の機能 | ヒント |
|---|---|---|
| 残業の偏りと 36 協定（月 45 時間）のチェック | SQL、Power BI | 勤怠の残業時間と残業申請を突き合わせられます |
| 年次有給休暇の取得状況（年 5 日の取得義務） | SQL | `attendance.leave_type` |
| 離職の要因分析・離職予測 | ノートブック | 残業・研修・部署・上長・通勤時間などを特徴量に |
| 退職面談コメントのテキスト分析 | ノートブック | 自由記述です |
| テレワーク率とオフィスの電力 | ノートブック、Power BI | 05 の本社（H01）の電力と組み合わせられます |

### 5. 施設・エネルギー（05_facility_energy）

| アイデア | 使う Fabric の機能 | ヒント |
|---|---|---|
| 外気温と電力の関係（冷暖房の V 字カーブ）、気温補正した省エネ効果 | ノートブック、Power BI | BEMS の外気温つき。気象庁データとも比較できます |
| 空調の設定変更の効果 | SQL | `hvac_settings_log` を時系列で結合（as-of 結合） |
| 夜間・休業日の無駄な電力の検出 | KQL、アクティベーター | 営業時間は `stores` にあります |
| 来店客数と電力・ガス | ノートブック | 01 の受注を 30 分単位に集計して結合 |
| 工場の生産とガス使用量 | ノートブック | 02 のセンサー値（焙煎機・オーブン）と比較 |

### 6. カスタマーサポートの問い合わせ（06_customer_support）

| アイデア | 使う Fabric の機能 | ヒント |
|---|---|---|
| 頻出語・カテゴリ別の特徴語（形態素解析） | ノートブック | `%pip install janome` などで試用版でも実行できます |
| 未分類の問い合わせの自動分類 | ノートブック（ルールベース、または外部の Azure OpenAI） | `category` が空の問い合わせがあります |
| 問い合わせが急増した原因の追跡 | ノートブック、Power BI | 受注・製造ロット・アプリログ・天気と照らし合わせてみてください |
| 対応時間と顧客満足度（CSAT） | SQL、Power BI | 初回回答・完了日時と `csat_score` |
| 本文からの注文番号・ロット番号の抽出 | ノートブック（正規表現） | 書き方の揺れがあります |

### 7. Excel 帳票（07_excel_reports）

| アイデア | 使う Fabric の機能 | ヒント |
|---|---|---|
| 書式の違う日報を 1 つの表にまとめる | ノートブック（pandas）、Dataflow Gen2 | 店舗ごとの書式は `data/07_excel_reports/README.md` |
| 発注書の品名を品目マスタに名寄せする | ノートブック | `master/supply_items.csv` が正式な品目一覧です |
| 日報の売上と POS の突合（転記ミスの検出） | SQL | 01 の受注と店舗・日付で結合できます |
| 日報の「天気」と気象庁の記録の比較 | ノートブック | 記号・ひらがな・漢字が混在しています |

### 8. アプリの操作ログ（08_app_logs）

| アイデア | 使う Fabric の機能 | ヒント |
|---|---|---|
| 閲覧 → カート → 購入のファネル分析 | ノートブック、Power BI | `purchase` イベントの `order_id` で受注とつながります |
| バージョン別・OS 別のコンバージョンとエラー | KQL、ノートブック | `app_releases.csv` にリリース履歴があります |
| プッシュ通知の効果 | ノートブック | `traffic_source` と `push_open` |
| 旧スキーマと新スキーマの統合 | ノートブック | 旧アプリはフラットな JSON・エポックミリ秒です |
| 店舗でのクーポン提示と来店 | ノートブック | `coupon_display` と 01 の店舗の受注 |

## データを組み合わせたアイデア（新規性のヒント）

すべて 1 つの会社のデータなので、部門をまたいだ分析ができます。

- **工場 → 品質 → お客様**：設備のセンサー値の変化と、製造ロット・問い合わせ・返品をつなげたトレーサビリティ
- **天気 → 来店・商品構成 → 電力 → 利益**：気温が売上とエネルギーコストの両方に与える影響
- **アプリの不具合 → 決済エラー → 問い合わせ → 機会損失の推定**
- **天候 → 配送遅延 → 問い合わせ → 顧客満足度**
- **残業・研修 → 離職 → 店舗の人手不足 → 売上**
- **問い合わせ → 法人のリード → 受注**：サポート経由の法人案件（`leads.source_inquiry_id`）
- **気象庁・家計調査などのオープンデータ**との組み合わせ

## Fabric の機能との対応

| Fabric の機能 | 向いているデータ |
|---|---|
| OneLake / レイクハウス | 全データ（Files にアップロード → テーブル化） |
| ウェアハウス（SQL） | 01・03・04（リレーショナルな分析、主キーを付けて GraphQL 公開） |
| Data Factory（パイプライン・Dataflow Gen2） | 07（帳票の統合）、外部のオープンデータの取り込み |
| ノートブック / Spark | 06（テキスト）、07（Excel）、08（JSON）、需要予測・離職予測 |
| Real-Time Intelligence | 02（センサー）、05（30 分値）、08（イベントログ） |
| Power BI | 全データ（ダッシュボード・レポート） |
